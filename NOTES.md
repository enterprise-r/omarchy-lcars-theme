# Maintainer notes

Working notes for the maintainer. Not user documentation. Last reviewed 2026-11-18.

## Direction

This repo is a hard fork of `yzingher/omarchy-lcars-theme`, which looks
abandoned. The original author's decisions are not binding; choices follow
good stewardship of the theme. MIT still requires keeping their copyright line
in `LICENSE`.

The theme becomes **Dark-R**: the Omarchy complement to the Enterprise-R UI
language at <https://www.enterprise-r.com/showcase/>. The showcase, and its
`palette.css`, are the **source of truth** for colors and roles. Where this
theme and the showcase disagree, the theme changes, unless we decide the
showcase should.

Plan: develop here in one repo for now, then split into a theme repo and an
add-on repo, and rename to `dark-r` after the split (see Roadmap).

## Role mapping

| Role | Showcase token | Where it applies |
|---|---|---|
| Hover / keyboard cursor | `--ui-accent` `#f0a202` | controls hover, launcher and menu selected row, workspace hover |
| Keyboard focus | `--ui-fg-bright` `#fff3e6` | controls focus |
| Current / chosen | `--ui-green` `#77af8a` (sage) | controls selected, current workspace, active indicators, selected tab (GTK3, Firefox, VS Code) |
| Other crumbs | `--ui-magenta` `#ba9eda` | occupied workspaces |
| Active line | `--ui-border-active` `#ba9eda` | Hyprland active border, lock field while typing |
| Card / panel | `--ui-bg-lighter` with `--ui-fg-dark` border | popups, tooltip, launcher, menu, notifications, polkit, lock field |
| Dim | `--ui-fg-dark` `#9385a5` | control borders, placeholders, empty workspaces, clock chip |
| Notices | blue info, green ok, amber warn, red error | notifications (info), bar attention (warn), errors (red) |
| App header | `--ui-border` `#3f2c53` (`.r-bar`) | libadwaita header bars, Firefox toolbar and tab strip |
| Text selection | `--ui-border` under `--ui-fg-bright` | GTK legacy selection |
| Links | `--ui-magenta-bright`, hover `yellow-bright`, visited `yellow` | GTK4, Firefox |
| Hover fill | solid `--ui-accent` with `--ui-bg` text, never a translucent wash | GTK4 buttons and sidebar rows, Firefox buttons, tabs, menus, lists; VS Code tabs, status bar, and the keyboard row in the launcher, suggestions and menus |
| Destructive | `--ui-red`, hover `bright_red`; never amber | GTK3, GTK4 and Firefox buttons |

Translucent amber over the dark surfaces reads as brown, and the
`currentColor` washes that libadwaita and Firefox use read as gray. Both
hooks therefore add a few rules on top of the variables: GTK4 for header
strips, hover, checked and selected rows, text selection, links and focus;
Firefox for toolbar icon and context menu hover. Firefox declarations are
`!important` because user sheets otherwise lose to its native GTK rules.

GTK3, GTK4, Firefox and VS Code take these from one `roles()` function,
copied into `scripts/gtk3.py`, `scripts/gtk4-libadwaita.py`,
`scripts/firefox-chrome.py` and `scripts/vscode-surfaces.py`. A test checks
that the copies are identical, and another that the hooks emit palette
colors only and, in CSS, no shape properties.
GTK3 is all rules: Adwaita-dark and Omagtk compile their colors in, and the
user sheet outranks either by priority. Checked on screen with a GTK3 widget
gallery under both base themes.

GIMP 3 layers its own Default theme over GTK3 and paints it from about
twenty `@define-color` names (gray `#3c3c3c` panels). With only the GTK3
sheet, GIMP showed Dark-R buttons on gray panels. `gtk3.py` now also writes
those names into a managed block in each `~/.config/GIMP/3.*/gimp.css`, which
GIMP imports after its theme. GIMP keeps light text on its hover and selected
fills, so those take `line`; the GTK3 sheet still gives buttons, menus and
rows amber hover and sage selection. Checked on screen 2026-11-19 (GIMP
3.2.6, dark scheme): welcome dialog, docks, rulers, layers list.

GTK3 menus: a menu or popover is styled as a CSS child of the item or
button that opened it, as a `window` or `popover` node, and that opener
stays `:hover` or `:checked` while the popup is open. The old
`menuitem:hover *` therefore made every label in an open menubar menu
`#0c040f` on the card, in any GTK3 app. Text-on-fill rules now go through
`inside()` in `gtk3.py`, which stops at `window` and `popover`; a test keeps
it so. Checked in GIMP: File menu with a submenu, the Mode dropdown, a dock
tab menu with check and radio items.

To look at a GTK3 app without touching the desktop: run `broadwayd :5`,
start the app with `GDK_BACKEND=broadway BROADWAY_DISPLAY=:5` (GIMP also
`--new-instance` and `GIMP3_DIRECTORY` pointing at a copy of the profile),
and drive `http://127.0.0.1:8085/` from headless Chromium over CDP.

The hooks recolor; shapes stay the base theme's. Where Adwaita GTK3 draws a
line with a box-shadow (focused entry, current tab) the rule repeats
Adwaita's geometry in a palette color.

VS Code exception: it has no hover color for match highlights or toolbar
icons, so trees, lists and toolbars hover with the quiet `--ui-border` fill;
amber would hide the amber matches and the light icons. In those lists the
keyboard cursor is a solid amber outline and the chosen row has sage text.

## Open inconsistencies

1. **Tokens the showcase lacks.** `colors.toml` also has `selection #41285b`,
   `muted #7d6d91`, `dark_background #0a030e` and `darker_background
   #09030d`. Omarchy's templates need them. Decide whether they join
   `palette.css` or stay theme-only. `muted` is 4.30:1 on the background,
   just under AA for text; the showcase would use `fg-dark` (5.90:1).
2. **Notices by kind.** Omarchy gives notifications one border color, so
   every notification looks like info. Urgency colors would need shell
   support.
3. **Hard-coded hex in plugins.** The shell's `Color` singleton exposes only
   foreground, background, accent, urgent and muted, so plugins write the
   other palette colors as hex. Every plugin also detects the theme with
   `Color.background === "#0c040f"`. Both break if the palette changes.
4. **Reduced motion.** The starfield runs all the time; it can only be
   hidden from the bar's context menu.
5. **Firefox context menus not seen on screen.** They follow the same rule
   as popovers, which were checked. GTK3 menus were checked 2026-11-19 (see
   GIMP above).
6. **Untested on screen.** The four commits above pass the installer tests
   but have not been checked visually yet.
